# ChatNote：从制作与修改反馈提炼的案例

本案例依据用户已明确表达的制作要求与修改反馈整理，用于学习判断方法。它不代表当前网站或插件版本的功能核验；复用具体功能描述前读取当前产品。不要把本案例的颜色、模块数或交互套用到其他产品。

## 1. 把功能推进到用户价值

- 使用情境：与 AI 长时间对话，回答很多，有价值的信息容易被后续对话覆盖。
- 核心动作：用户在阅读过程中选择值得留下的内容，即时摘录至侧边文档。
- 已认可的价值表达：“让有价值的回答，即时被记录”。
- 判断方法：从“一键摘录、Markdown 编辑”等能力出发，继续追问用户为什么需要它；最终用具体困扰和获得的结果写首屏。不要只写“边聊边记”“提升效率”，也不要擅自把用户主动选择的价值改成自动总结。

## 2. 用画面证明功能

| 要表达的能力 | 应出现的证据 | 容易出现的失败 |
| --- | --- | --- |
| 即时摘录 | 对话中选中文字，附近出现添加入口，侧边文档出现相应内容 | 只展示两个窗口，看不出内容如何过去 |
| 每个 Chat 独立文档 | 切换两个不同话题，再返回原话题，显示各自对应文档 | 换话题后仍显示相同文档，或没有关联线索 |
| 本地实时保存 | 当前版本真实保存位置、状态或文件结果 | 仅放文件夹图标就宣称已证明同步 |
| 一键交给 AI | 文档内容被加入输入框的前后状态 | 仅用箭头描述，没有结果 |

## 3. Hero 动效的关键验收

按需要展示打开文档、摘录标题、摘录表格、切换话题摘录、返回原话题等步骤，不强求将全部功能塞入一条动画。

- 选中表现必须一致：选区覆盖目标文字，不能用整行色块冒充精确选区；第三次选择也要按前两次同样标准检查。
- 添加入口接近实际选区，鼠标移动距离与真实交互一致；表格入口遵循产品的真实悬浮位置。
- 长对话滚动应有连续上下文，可弱化非重点，不能突然换掉内容。
- 每次点击只添加一次。完成最后一次添加后保持完成态，轻微过渡后从起点重新开始；不要复写第三条、闪空白页或出现无意义尾段。
- 检查最后一帧到第一帧，不能只检查动作中段；记录至少两个完整循环的观察结果。

## 4. 视觉与迭代经验

- ChatNote 大小写统一；保留已确认的核心价值、独立文档关系与真实产品行为。
- 用户最终偏好清晰白底；曾尝试渐变不意味着以后都加渐变。
- 适度拉开模块标题和正文间距，相关内容沿共同轴线对齐。不要为装饰添加无帮助的图标。
- 首先判断问题属于文案、画面、布局还是动作，再做对应范围修改。改背景时不要重做产品界面；修选区时不要换掉已通过的动画脚本。

## 5. 迁移到下一产品

复用“场景困扰 → 关键动作 → 用户结果 → 画面证据 → 验收”的推导方法。重新读取新产品事实，重新决定配色、页面长度、模块关系与动效形式。
