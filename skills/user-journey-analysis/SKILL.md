# 用户旅程分析

## 1. 确定分析边界

从已有材料提取角色、场景、目标、待支持的产品决策及现状/目标状态。用一句话界定旅程：“作为［角色］，在［场景与约束］下，希望［可判断是否达成的目标］。”

- 只保留影响任务的能力、工具和环境；不编造人物背景，不用年龄或残障等级推断能力。
- 每张图聚焦一个角色、一种场景、一个目标；关键路径不同则分图，现状与设想分开。
- 角色、场景或目标缺失且会改变分析时，先补问；缺调研材料时可做假设版，明确待验证项。
- 用户要求“一天的场景”时，按时间盘点独立任务，不将其冒充同一目标的完整旅程；需分析具体体验时，再展开对应任务。

## 2. 拆分完整阶段

从需求产生到目标达成、放弃或失败，按用户任务进展拆分，通常为 4–7 段；不为凑数拆分，也不只列产品内页面。纳入影响结果的产品外行为、线上线下触点及必要的使用后环节。

记录有证据的回退、跳过与分支；关键路径差异大时拆图，避免拼成无人经历过的流程。

## 3. 填写旅程矩阵

列为阶段，行为、触点、想法、痛点、情绪、机会为行。先还原经历，再推导机会；没有痛点的阶段无需硬填。

| 维度 | 填写规则 |
| --- | --- |
| 行为 | 用户实际做了什么，写可观察动作，避免用功能名替代行为。 |
| 触点 | 与谁、通过什么渠道或界面交互，包括产品外触点。 |
| 想法 | 优先引用与该阶段相关的用户原话；转述不加引号，推测标为假设。 |
| 痛点 | 写明具体障碍、发生条件及对目标的影响；有现有解法时说明其局限。 |
| 情绪 | 写感受及依据；量化与曲线规则见下文。 |
| 机会 | 写针对该问题可改善的结果；具体方案及验证放入机会表。 |

给访谈、观察、客服记录和行为数据分配来源编号，标注可回查位置、适用人群与时间；矩阵中的关键判断引用编号。区分观察事实、用户自述、分析推断与待验证假设。原话证明该用户有此感受，不证明普遍性；行为数据不能直接证明内心想法或情绪。

情绪曲线优先采用用户自评，并注明量表、方向与采集方式。需要分析者估计时，使用统一尺度（如 −2 很负面至 +2 很正面），逐点标注为估计并写依据；缺依据记“未知”，曲线留空，不补零、不跨缺口连线。不混用自评分与估计分，不把顺序阶段的折线解释为连续测量。

## 4. 将低谷转为可验证机会

沿“低谷或断点 → 为什么 → 具体问题 → 证据/假设 → 机会 → 验证”推导。情绪低谷是调查线索，不等于已证实痛点；无明显低谷但阻碍目标的问题也应保留。

每个候选问题写成：“在［条件］下，用户因［障碍］无法/难以［行为］，导致［影响］。”原因无证据时标为假设，并说明如何核实。

| 阶段 | 具体问题 | 证据与待验证原因 | 改善机会/候选方案 | 验证方法与指标 | 优先级及依据 |
| --- | --- | --- | --- | --- | --- |

- 方案对应问题，写清触发条件、用户动作与预期结果；不把候选功能写成已实现能力。
- 验证先检验问题与原因，再检验方案；未证实的问题优先安排访谈、观察或数据核查。
- 指标对应用户目标，注明人群、起止事件、计算口径与观察窗口；按需设副作用护栏。无基线时先采集，不编造改善幅度。
- 优先级综合目标受阻程度、影响范围/频率、证据强度和实施成本；信息不足时给出暂定排序与补证事项，不按情绪最低直接定优先级。
- 对比现有方案时核验真实能力，指出具体条件下的增量价值；设备场景另查身体动作、注意力、网络、隐私等前提。腕上辅助案例见 [examples.md](references/examples.md)。

## 5. 交付与自检

无格式要求时，交付旅程边界、矩阵、机会表及来源/待验证项。用户只要评审或局部修改时，限定在该范围；已确认内容按反馈保留。要求先确认文案时，停在文案；要求直接制作时继续交付。

需要图片或可编辑 PPTX 时，读取 [可视化交付](references/delivery.md)。

交付前检查：

- 角色、场景、目标明确，阶段覆盖起念到结果，分支和分析边界可解释。
- 行为、触点、想法、痛点互不混写；事实可追溯，假设不伪装为原话或数据。
- 情绪来源与尺度清楚，无依据处留空；每个低谷已解释为问题或列出调查问题。
- 机会对应问题，方案有验证方法与指标；证据不足处不下确定结论。
