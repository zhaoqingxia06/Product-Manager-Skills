# 问卷分析与 HTML 报告

以用户研究专家和产品经理视角完成数据到报告的完整任务。默认直接交付离线可打开、移动端可读的 HTML，而非只给分析思路或等待逐步确认。用户指定其他格式时遵从。资料不足时先完成有依据的部分，标明缺口；只有无法识别或读取关键数据时才询问。

## 执行

1. 读取所有相关原始数据、问卷和背景，确认研究目的、决策、样本来源、体验或概念阶段。未给目的时根据题目推测并明确标注；禁止将推测称为已确认。
2. 围绕产品决策建立研究问题—题目—可回答范围—方法对应关系，明确证据缺口；检查题型、编码、跳题、缺失、重复、互斥冲突和有效样本。不得凭猜测删除；重要异常做含/不含敏感性对照。记录每项分子、分母、排除和多选口径。读取 [分析方法](references/analysis-methods.md)。
3. 围绕研究问题先分析整体，再主动提出并筛选能影响决策的交叉：说明分析问题、选取题目与人群、比较结果及证据边界；检查反例和开放题。筛选交互不能替代主动分析。探索多个交叉但不机械穷举，不因差异而认定因果或普遍性；小样本和探索发现说明局限。数据只给汇总时不得构造个体或假装能筛选。
4. 重点洞察写清事实与证据、产品含义和待验证问题；根据资料关联用户问题、现有解决方式及功能价值，无证据不推断问题已解决。每项验证建议关联发现，写明找谁、验证及观察什么；原因无证据时作为假设。原话准确、匿名，含少数重要反例。不能伪造原题、回答、原因或用户画像。参考 [证据与洞察](references/evidence-and-insights.md)。
5. 【强制】同一分析问题中可用一张表清楚呈现及比较的数据，必须合并成一张表，不拆成多个图表；表中明确指标、分母、原题及必要口径，并保留直接点击筛选与联动。只有数据维度或阅读性导致一表无法清晰表达时才拆分。按研究目标组织清晰章节，串联人群、经历或问题与相关产品判断；结论先行，呈现样本、分析、产品含义、限制及下一步验证；章节内容随数据变化，概念评价不等同实际行为或购买。图表附原题、人数、比例、分母、必要口径；无原题明确标注未提供。阅读 [报告与交互](references/report-and-interaction.md)。
6. 使用同一结构化统计结果生成图表及相关数字，检查计算、样本分母与用户原话；验证页面本地打开、移动端、筛选和无数据状态，不能验证的项目明确报告。将可分享文件按当前环境的持久化文件工作流保存后提供链接。

## 筛选和交付

逐人数据可用时，默认让用户直接点击基本信息图表里的选项/条形/标签进行筛选并联动刷新其他图表；不要把独立的顶部筛选区当作唯一筛选入口。图表内明确提示可点击、选中高亮、再次点击取消，未选中的选项即使当前计数为零也保持可选以支持多选。可用吸顶状态条展示已选条件、人数及清除按钮：合计最多5项，同一维度选项为或、不同维度为且；显示条件和人数，支持取消和清空，重算各题有效分母，处理零样本，避免把全样本固定洞察套到子群。默认 n<30 仅作谨慎提示，不意味着 n≥30 便有统计可靠性。

本地分析版可能包含逐条答卷，必须明确告知；明确要求分享时优先交付不含逐人数据的汇总版，检查小群体及组合可识别风险，安全与交互不可兼得时限制筛选并说明。不要把去名视作匿名。

用户认可的四功能报告仅是分析与表现参考：蓝色主题、结论先行、数据与原题相邻、交叉探索和待验证问题。不得固定功能价值、试用或购买意愿为所有问卷的章节，也不复制其数据。
