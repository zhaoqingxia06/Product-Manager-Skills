# 埋点设计需求文档生成

根据原型图分析结果，生成 Excel 格式的埋点设计需求文档。

## 核心分工

**产品经理（你）负责**：把埋点需求写清楚——为什么要埋、什么时机上报、能产出什么指标。

**埋点设计师负责**：整理上报参数的具体格式和字段定义。

AI 辅助时重点帮你把「埋点需求及目的」写得具体、可度量，参数列保持精简即可。

## 工作流程

### 首次生成

1. **接收原型图** → 用户上传图片（PNG/JPG），用浏览器打开查看内容
2. **逐页分析** → 识别每个页面的 UI 元素、交互动作、用户路径
3. **识别埋点** → 标注所有需要埋点的曝光、点击等行为
4. **生成文档** → 运行 `scripts/generate_tracking.py --init` 创建初始文档
5. **追加埋点** → 运行 `scripts/generate_tracking.py --append` 追加埋点数据
6. **去重检查** → 脚本自动检查并清理重复行

### 追加新模块

1. 接收新原型图，分析内容
2. 准备 JSON 格式的埋点数据
3. 运行 append 命令追加
4. 脚本自动去重

## 文档规范

### Sheet 1：埋点总表

| 列 | 说明 |
|---|---|
| A | 原型图截图（嵌入图片） |
| B | 页面（绿色=点击，橙色=曝光） |
| C | 事件名称（snake_case 命名） |
| D | **埋点需求及目的**（重点列！写具体业务价值，不要泛泛的"统计UV/PV"） |
| E | 上报时机 |
| F | 上报参数（精简，默认3个公共参数 + 必要业务参数） |
| G | 统计指标（写具体指标名，如"点击XX的用户数、次数"） |

### Sheet 2：公共参数

包含 11 个全局参数：device_id、event_count、timestamp、user_id、app_version、os_type、os_version、network_type、session_id、page_id、channel。每个参数都标注了数据价值说明。

## 数据格式

### 埋点 JSON 格式

```json
{
  "events": [
    ["页面名称", "事件名称", ["目的1", "目的2"], "上报时机", "特有参数", "统计指标", "点击/曝光"]
  ],
  "page_to_img": {
    "页面名称": ["图片文件名", x起点比例, y起点比例, 宽度比例]
  }
}
```

### 上报参数格式

默认 3 个公共参数 + 少量关键业务参数，同一单元格内换行：
```
device_id：用户数
event_count：次数
timestamp：上报时间点
tab_id：Tab标识
```

### 埋点需求及目的格式（重点列）

**写具体业务价值，避免泛泛的"统计UV/PV"。** 多个目的同一单元格换行展示：

```
APP&月活、日新增、3日/7日留存、活跃时间
进入APP的用户数、次数
```

```
单次使用时长、单次输入句子长度
```

```
统计复制操作用户数、次数
```

### 统计指标格式

写具体指标名，不要泛化：
```
点击【语音翻译】的用户数、次数
进入设置的用户数、次数
使用【复制】的用户数、次数
```

## 执行命令

### 初始化文档
```bash
python scripts/generate_tracking.py --init --output "埋点设计需求文档.xlsx"
```

### 追加埋点
```bash
python scripts/generate_tracking.py --append \
  --output "埋点设计需求文档.xlsx" \
  --img-dir "./原型图目录" \
  --events "./events.json"
```

详细 UI 模式埋点模板见 `references/tracking_patterns.md`。
