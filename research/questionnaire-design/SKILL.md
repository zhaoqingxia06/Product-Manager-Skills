# Questionare-design：用户问卷设计

## 目标与流程

围绕研究问题设计可量化、可分析的题目，为产品决策提供证据。

1. 明确产品阶段、研究目标、目标人群、发放场景和结果用途；关键信息不足时先确认。
2. 按研究目标选择内容，建立「研究问题 → 所需信息 → 题目 → 分析用途」的对应关系。
3. 对每题用 5 Why 追问：要获取什么、为什么需要、与目标如何关联、如何分析、支持什么判断。删除无法服务目标的题目。
4. 根据用户经历设置题序和跳题，完成问卷；按下方规则逐项检查后输出。

## 不同阶段的研究重点

| 产品阶段 | 问卷类型 | 重点 |
| --- | --- | --- |
| 机会探索 | 用户画像与需求 | 用户特征、场景、行为、困难、现有解决方式 |
| 概念设计 | 概念与价值验证 | 目标场景、感知价值、使用意愿、顾虑 |
| 原型与测试 | 体验评估 | 任务完成情况、操作困难、功能体验、改进需求 |
| 上线初期 | 使用与体验 | 接触和使用情况、使用场景、功能评价、未使用原因 |
| 成长与迭代 | 满意度与留存 | 使用频率、满意度、持续使用意愿、流失原因 |
| 产品成熟 | 推荐与优化 | 推荐度、推荐原因、关键需求、改进优先级 |

研究阶段和类型可组合；按目标选择，勿机械套用。实际体验和观看介绍后的预期分开询问。

## 问卷设计规则

### 基础信息

- 包含姓名（选填）、年龄、性别、职业，以及与研究目标相关的属性；性别选项为男、女，职业为填空题。
- 根据研究对象补充属性：如听障用户的听力等级；eBike 用户的身高、体重、家庭地址。按研究需要确定属性与地址的具体粒度。

### 题目和选项

- 每题表达清楚、简短自然，让不同认知水平的人容易理解；全文统一人称和产品名称。
- 选项先系统分类，再尽可能覆盖相关情况；含义明确、避免重复。例如场景题按有意义的维度分类列举。
- 多选题标明上限，一般最多选 3 项，提示「请选择你认为最重要的选项，最多 3 项」；最后一项为「其他，请填写：___」。
- 填空题一般选填，其他题目必填；不提供「说不清」「不愿透露」等回避性选项。提供真实存在的情况，例如「未使用过」或「没有」，并跳过不适用题目。
- 同一问题评价多个功能时优先使用矩阵量表；满意度、价值感等程度题采用 5 个等级，同类题保持方向和表述一致。若使用 NPS，推荐度采用 0–10 分，避免混用五级量表。
- 最后一题询问是否愿意参加访谈，联系方式选填并说明用途。

## 输出与检查

输出可审阅的文本问卷：标题、简短说明、题目、题型、选项、必填或选填、选择上限、量表和跳题。检查题目是否服务目标、选项是否完整清楚、题序及跳题是否成立、量表和用语是否一致。

若用户要求制作腾讯问卷，先检查腾讯问卷 Skill 是否可用；未安装时协助安装或说明限制，未实际创建时不声称有问卷链接。

## 后续经验维护

新增经验时按「适用条件 → 具体规则」补充到相应章节；仅适用于特定研究或产品的内容注明范围。合并重复规则，遇到冲突先说明并以用户最新要求为准，保持内容简洁。
